# examples / retrofit-67s：把 3D 黏土角色接進既有解說長片

這是《Puti-AI 天氣小學堂》**67 秒版**實際使用的控制層與組裝器，從正式專案原封搬出來。
用法與原理請先讀：[3D 黏土角色接入既有長片：實戰筆記](../../3D黏土角色接入既有長片-實戰筆記.md)。

- 原片：67 秒 / 8 幕 / 23 條字幕 / 配音已定案 / 固定攝影機（無運鏡）
- 這裡**不含**音檔、字型、Three.js vendored 檔與 mp4，只放「可以直接看懂並搬走」的兩支程式

| 檔案 | 作用 |
| --- | --- |
| `build.py` | 組裝器：抽出既有長片的 CSS／markup／GSAP，抽出黏土引擎的 3D 區塊，插入 `ctrl.js`，輸出自包含 `index.html` |
| `ctrl.js` | 控制層（本範例的主角，504 行）：固定攝影機、螢幕像素走位表、七通道情緒表、跳躍／旋轉／落地壓縮、表情與特效 |

---

## 一、它解決什麼問題

原本這支片子的小吉是**平面 DOM 吉祥物**（8 個 `.mascot` div + 16 條 GSAP tween）。
要換成 3D 黏土角色的話，直覺做法是「重做一支片」，但配音與字幕已經定案，重做等於重對 23 句時間。

所以改成**三層不改、只換演員**：

```
既有長片（只讀）        黏土引擎（只讀）
  CSS / markup / GSAP     角色 / 材質 / 表情零件 / 特效
        \                    /
         \                  /
          ▼                ▼
        build.py  ──►  index.html（自包含，勿手改）
                          ▲
                 ctrl.js（我寫的唯一檔案）
```

`build.py` 具體做了 6 件事：

1. 抽 `<style>`，順手把 3 處在奶油底上太淡的橘字壓深（`#d96b44` → `#b4502c`，對比度才過 AA）
2. 抽 `#root` markup，**移除 8 個 `.mascot`** 區塊
3. 在 `.floor` 之後插入 `<canvas id="stage" class="clip" data-start="0" data-duration="67">`（z-index 5，在文字之下）
4. 抽 GSAP 區塊，**移除 16 條小吉 tween**（跨行 tween 要一路吃到分號，否則會留下孤兒 `{ }` 造成 `page_error`）
5. 抽黏土引擎的 3D 區塊，把 `scene.add(煙/雲/雨)` 改成 `hero.add(...)`（特效跟著角色走）
6. 把引擎原本的「鏡頭 + 動畫」整段換成 `ctrl.js`

## 二、前置需求：引擎要提供什麼

`ctrl.js` 不是獨立模組，它是**接在黏土引擎後面的控制層**，直接操作這些既有變數（本範例來自
`clay3d/index.html` 的角色建構段）。移植到別的引擎時，把這些名字對上即可：

| 類別 | 需要的東西 |
| --- | --- |
| 場景 | `scene`, `camera`, `renderer`, `W`, `H` |
| 角色 | `hero`（外層，負責位置／縮放／旋轉）, `body`（內層，負責壓縮拉伸） |
| 材質 | `clayMat`（臉底色）, `cheekMat`（腮紅）, `S`（色票 `S.gold/angry/sad` 等） |
| 五官 | `eyeL/eyeR`, `happyL/happyR`, `eyesGroup`, `browL/browR`, `smile/frown/flatMouth/ohMouth` |
| 特效 | `sweat`, `tearL/tearR`, `puffs`, `bolts`, `angerLight`, `cloudGroup/cloudMat`, `rainGroup/rainMat/drops` |
| 陰影 | `heroShadow`（唯一的地面接觸陰影） |
| 工具 | `clamp01`, `lerp`, `prog(t,a,b)`, `eio(u)`, `sm(t,a,b)`（smoothstep） |

> 大原則：`hero` 只管「在哪裡、多大、轉幾度」，`body` 只管「壓扁拉長」。
> 兩者分開，落地回彈才不會把位置也一起縮掉。

## 三、只要改三個表

整支片 67 秒的演技與走位，全部壓在三個資料表裡：

### 1. `EMO`：七通道情緒（時間, joy, wow, ner, ang, sad, cold, wind）

```javascript
const EMO = [
  [16.80, 0.15, 0.00, 0.15, 0.00, 0.00, 0.90, 0.55],  // 冷到發抖
  [25.95, 0.05, 1.00, 0.05, 0.00, 0.05, 0.35, 0.10],  // 嚇到
];
```

相鄰 keyframe 線性內插，所以「冷 + 擔心」這種複合情緒會自己長出來。
共 63 個 keyframe 鋪滿 67 秒。

### 2. `POS`：走位（時間, 腳底 x, 腳底 y, 身高 px, 動作）

動作只有三種：`slide`（急滑，二次緩出）、`walk`（小跳步，自動算步數）、`hold`。

```javascript
const POS = [
  [0.00, 1580, 606, 190, "slide"],   // 從右外側滑進場
  [1.02,  224, 636, 186, "hold"],    // 煞停
  [2.28,  224, 636, 186, "walk"],
  [2.72,  314, 632, 186, "hold"],
];
```

`py` 就是「腳踏在設計稿第幾像素」，可直接跟版面稿對照。

### 3. `JUMPS` / `SPINS`：加碼節拍

```javascript
const JUMPS = [[3.86, 26, 0.34], ...];   // [起, 高度 px, 長度 s]
const SPINS = [[12.42, 0.78], [62.88, 0.52]];  // 360 度旋轉，[起, 長度]
```

`IMPACT`（落地壓縮）不用手寫，會自動由 `POS` 的 walk 段與 `JUMPS` 推算：

```javascript
JUMPS.forEach((j) => IMPACT.push([j[0] + j[2], 0.35 + j[1] / 70]));
```

## 五、移植到你的片子的 6 步

1. **量邊界**：把每一幕「卡片底部 y」寫成表（見上表），角色身高先訂 `可用高度 × 0.92`。
2. **找翻頁**：列出所有轉場時間與長度，安全窗是 `起點 + 0.42 ~ + 1.02`（1.2s 的翻頁）。
3. **填 `POS`**：先讓角色「站對位置、不動」，抽格確認不壓字、不被切頭。
4. **填 `EMO`**：對照每句台詞貼情緒，允許重疊與疊加。
5. **加 `JUMPS` / `SPINS`**：只在語氣重音處加，不要每句都加。
6. **抽格驗收**：`check → snapshot 抽格 → 親眼看`，最後才 render。

## 六、幾個一定要知道的坑

| 坑 | 後果 | 解法 |
| --- | --- | --- |
| 用世界座標走位 | 改一次鏡頭／fov，全部站位重算 | 用 `mark(px, py, hpx)`，以螢幕像素為舞台座標 |
| 3D canvas 疊在文字上 | 字幕被角色吃掉 | canvas `z-index: 5`，文字 `z-index: 10+` |
| 刪 GSAP tween 沒吃到分號 | `page_error: Unexpected token ':'` | 迴圈吃到 `;` 為止（`build.py` 有實作） |
| 特效掛 `scene` | 角色一走，煙留在原地 | `hero.add(...)` |
| 黃色混藍灰當「難過」 | 角色變土褐色，看起來髒 | 改混高明度暖灰／近白冷色（見筆記第七節） |
| 表演排在版權頁之後 | 演出被版權頁整片蓋掉，等於白做 | 抽 `credit` 起點前 0.5s 的格子確認看得到 |
| 先渲染再檢查 | 每次多花 80 秒 | 先 `snapshot` 抽 8 格（每格 4–6 秒） |
